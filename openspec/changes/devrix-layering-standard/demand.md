# Devrix 分层 ID 规范标准化

## 1. 背景

Devrix 作为多智能体开发助手，当前缺乏统一的 ID 规范来标识业务能力（需求、功能、测试）。现有代码中：

- 功能点散落在各模块，缺少统一前缀
- 测试用例与业务能力无直接映射
- PR/Issue 中难以快速定位相关代码

## 2. 需求描述

### 2.1 核心问题

| 问题 | 影响 |
|------|------|
| 功能点无统一 ID | PR/Issue 难以定位代码 |
| 测试与业务无映射 | 回归风险增加 |
| 多模块协作缺乏导航 | 定位成本高 |

### 2.2 目标状态

- 所有功能点具备 D-S-A-F-T 五层 ID
- 测试用例可追溯到业务能力
- 代码注释包含 ID 前缀
- 文档与代码 ID 一致

## 3. 验收标准

| ID | 标准 | 优先级 |
|----|------|--------|
| AC1 | D-S-A-F-T 规范文档发布至 `specs/architecture/` | P0 |
| AC2 | 核心模块（D01-D06）ID 映射完成 | P0 |
| AC3 | 新增功能点必须包含 ID 前缀 | P0 |
| AC4 | 测试用例包含对应功能 ID | P1 |
| AC5 | ID 生成脚本可用 | P2 |

## 4. 依赖与约束

| 类型 | 内容 |
|------|------|
| 依赖 | 无外部依赖 |
| 约束 | 不修改生产代码逻辑 |
| 约束 | 不引入新依赖 |

## 5. L1–L5 映射草案

| 层级 | 资产 |
|------|------|
| L1 | Architecture |
| L4 | ID 规范、标准文档 |
| L5 | L4-1-01~03 (规范定义、代码映射、扩展规则) |

## 6. 变更范围

### 6.1 新增

- `specs/architecture/layering-standard.md` — 标准规范文档
- `scripts/generate-id.go` — ID 生成脚本（可选）

### 6.2 修改

- `README.md` — 添加 ID 规范引用
- `AGENTS.md` — 添加 ID 规范说明

### 6.3 不变更

- 生产代码逻辑
- 测试逻辑
- 配置文件

## 7. 风险评估

| 风险 | 影响 | 缓解 |
|------|------|------|
| ID 长度增加维护成本 | 低 | 仅标注，不强制转换现有代码 |
| 规范与现有代码不一致 | 中 | 从新功能开始执行 |
